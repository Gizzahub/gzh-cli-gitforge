# 반복 개발 검사

`DVA_BASE=origin/master dva ci dev`는 기존 영향 선택기로 변경 패키지와 역방향 테스트
의존성을 고른 뒤 CLI build, 선택 패키지 vet, 테스트를 실행한다. 기준 ref는 명시해야 한다.
시간 예산은 초기 정책값이며 측정한 성능 보장은 아니다.

선택기는 커밋된 변경, staged, unstaged, untracked 입력을 포함한다. 삭제·이름 변경,
공용 설정·검사기·알 수 없는 입력, 느린 integration 패키지가 포함되면 좁은 검사를 실행하지
않고 전체 검사 필요 상태로 끝난다. 이 결과는 통과가 아니다. 이 프로파일 자체를 수정할
때도 전체 검사를 요구한다.

`make verify-dev`는 같은 개발 검사 진입점이다. `make verify-affected`는 테스트만 실행한다.
개발 검사는 소스를 포맷하거나 도구를 설치하지 않는다. 필요한 도구·의존성은 검사 전에 준비한다.

`dev` 성공은 `commit`이나 `full` 성공을 대신하지 않는다. 기존 커밋 전 보안·린트 검사와
통합 전 `make verify-full` 계약은 그대로 적용한다. CI 실행 ID·시간·선택 범위를 근거로
남기며, 비교 측정 전에는 속도 개선 수치를 주장하지 않는다.
