# 0.14.1 릴리스 준비

호환되는 버그 수정이므로 patch를 올린다. `VERSION`과 개발 기본 버전은
0.14.1이며 공개 계약의 제거는 없다. 릴리스 노트는 생성하므로 CHANGELOG를
수기로 수정하지 않는다.

## 포함 수정

- `f09b8d72883d9664961b09a3a3c98468520df2c5`: sibling 소스 검사에서 정확한
  `.ce-metrics` 구성요소 바로 아래의 유효한 날짜·시각 session JSON만 untracked
  예외로 허용한다. tracked 변경은 계속 거부하며 archive는 커밋된 객체만 담는다.
- `26eafe11b9cdbe3138cb4eacc1f9f1bf48b5146d`: 짧은 blame hash를 무조건 8자로
  자르던 panic을 수선한다. 짧은 값은 보존하고 긴 값의 기존 8자 출력은 유지한다.
  회귀는 실제 raw Git token이 8자 미만임을 확인한 뒤 CLI 출력 보존을 검증한다.

## 검증·게시 경로

필수 `make verify-release`는 source master CI, 전체 gate, GoReleaser 설정 검사,
비게시 snapshot packaging 순서다. snapshot은 공식 stable 설치 증거가 아니다.
이전 버전 후보의 full PASS를 새 후보에 재사용하지 않는다.

공식 `.github/workflows/release.yml`은 VERSION 변경이 통합된 master push의 CI가
성공한 뒤 그 SHA를 태그하고 같은 job에서 릴리스와 Homebrew cask를 게시한다.
실패한 source CI를 수동 tag로 우회하지 않는다. 게시 후 tag SHA·archive checksum·
cask 버전과 digest를 확인하고, 로컬은 공식 cask 채널로 갱신해 두 version surface와
실제 실행 경로를 검증한다. source binary 덮어쓰기나 PATH 변경으로 대체하지 않는다.

이 문서는 동결 후보의 검증 요구를 기록한다. 실제 결과는 해당 SHA의
[CI 실행](https://github.com/Gizzahub/gzh-cli-gitforge/actions/workflows/ci.yml),
[Release 실행](https://github.com/Gizzahub/gzh-cli-gitforge/actions/workflows/release.yml),
[공식 릴리스](https://github.com/Gizzahub/gzh-cli-gitforge/releases/tag/v0.14.1)를 따른다.
