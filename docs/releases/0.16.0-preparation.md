# 0.16.0 릴리스 준비

공개 동작이 호환되지 않게 바뀌므로 patch가 아닌 minor를 올린다. bulk 명령의
저장소 선택, `commit`의 메시지 맵 처리, `diff`의 경로 표기가 바뀐다. 0.x에서
BREAKING 변경은 minor로 올린다. 릴리스 노트는 생성되므로 CHANGELOG을 수기로
수정하지 않는다. 각 변경의 이유와 BREAKING 내용은 커밋 본문에 있다.

## BREAKING 변경

- `2c230d3b` bulk 저장소 선택: 모든 bulk 명령이 `--select listed|all`로
  선택을 통일한다. `listed`에서는 설정 파일의 workspaces가 대상 전체이고
  `--repo`는 그 안에서 좁힌다. 선언되지 않은 `--repo`는 오류다.
  `--include`·`--exclude`는 스캔 디렉터리 기준 상대 경로에 매칭한다.
- `4caf707a` `commit`: `--stage all|tracked|staged`, `--file <path|->`,
  `--auto-message`를 추가한다. 메시지 맵이 변경 있는 저장소를 빠뜨리면
  `--auto-message` 없이는 아무것도 커밋하지 않고 멈춘다. 스캔 디렉터리
  자신의 저장소는 `.`으로 보고한다(basename 키도 계속 받는다). 명시한
  `--json`·`--yaml`을 파이프 stdin이 덮어쓰지 않는다. submodule이 아닌
  중첩 저장소는 스테이징하지 않는다.
- `bb97cb59` `diff`: 저장소 경로를 `commit`과 같은 상대 경로로 보고하고
  스캔 디렉터리 자신은 `.`이다. JSON의 `truncated`는 false여도 항상
  나온다. 중첩 저장소는 모든 형식에서 `nested_repos` 등으로 이름을 알린다.

## 그 밖의 포함 변경

v0.15.0 이후 master의 나머지 커밋(설정 경로 규칙 통일 ISSUE-391·404,
`workspace list` 읽기 전용 명령, go1.27.4 툴체인, 테스트 샤딩, CI·문서
정리 등)을 함께 담는다. 전체 목록은 생성되는 릴리스 노트를 따른다.

## 검증·게시 경로

위 세 변경은 각각 독립 리뷰와 `make verify-full`(exit 0)을 거쳐 master에
통합되었다(`bb97cb59`). `make verify-release`가 `bb97cb59` master에서
통과했다(master push CI, 전체 gate, GoReleaser 설정 검사, 비게시 snapshot
packaging, 2026-11-23). 이 준비 커밋은 버전과 문서만 바꾸므로 그 게이트
증거가 그대로 적용된다. 커밋 통합 후 master CI가
성공하면 `release.yml`이 VERSION 0.16.0 > 모든 기존 태그 조건을 보고 그
SHA에 `v0.16.0` 태그를 만들어 같은 job에서 릴리스와 Homebrew cask를
게시한다. 태그는 손으로 만들지 않는다.

게시 후 tag SHA·archive checksum·cask 버전과 digest를 확인한다. 호스트 cask
갱신은 이 릴리스와 별도의 devenv 작업으로 남긴다.

실제 결과는 해당 SHA의
[CI 실행](https://github.com/Gizzahub/gzh-cli-gitforge/actions/workflows/ci.yml),
[Release 실행](https://github.com/Gizzahub/gzh-cli-gitforge/actions/workflows/release.yml),
[공식 릴리스](https://github.com/Gizzahub/gzh-cli-gitforge/releases/tag/v0.16.0)를
따른다.
