# 0.9.2 릴리스 준비

`VERSION`과 `version.go`의 개발 기본 버전을 0.9.2로 맞춘다. 공개 최신 stable은
2026-10-14 조회 기준 `v0.9.1`이다. 기존 공개 계약을 복원하는 native finish READY와
승인된 provider rollout의 CE 참조 검증을 포함하므로 patch를 올린다.

게시 경로는 `.github/workflows/release.yml`의 `v*.*.*` 태그 트리거다. 워크플로는
Go 1.27.2와 GoReleaser 2.18.2로 릴리스와 Homebrew cask를 게시한다.
준비 검증은 `make quality-check`, `make release-check`,
`make release-dry-run`이며 마지막 명령은 `--snapshot --skip=publish`를 사용한다.
snapshot 결과는 정식 stable 설치나 TASK302 인수 증거를 대체하지 않는다.

## 검증 상태

독립 strong 리뷰는 PASS다. `mise exec -- dva provision tools`는 exit 0이며
프로젝트가 선언한 `bin/tools`만 준비했다.
`mise exec -- dva quality-check`가 기존 `make quality-check`를 실행했으며
실제 종료 코드 0이다. format·lint·보안·build·install audit·unit·integration·E2E와
critical coverage floor를 모두 통과했다. 이 저장소의 미정의 `make check`는
catch-all recipe로 성공 처리되므로 검증 근거로 사용하지 않았다.

설치된 GoReleaser mise shim에는 선택된 버전이 없어 Make 릴리스 명령을
그대로 실행할 수 없다. 기존 TASK-281의 exact-version 실행 선례에 따라
아래 명령으로 동일 설정과 비게시 인자를 검증했다. DVA manifest에는 릴리스
명령이 없어 직접 실행했으며 전역 설치·pin·PATH 변경은 하지 않았다.

```bash
GOWORK=off mise exec -- go run github.com/goreleaser/goreleaser/v2@v2.18.2 check
GOWORK=off mise exec -- go run github.com/goreleaser/goreleaser/v2@v2.18.2 release --snapshot --clean --skip=publish
```

두 명령 모두 exit 0이다. snapshot은 `0.9.2-next`이며 darwin amd64/arm64,
linux amd64/arm64, windows amd64의 5개 archive와 cask를 생성했다.
5개 SHA-256을 별도로 대조해 통과했다. macOS arm64 바이너리는 Go 1.27.2,
`0.9.2-next`를 보고하며 `--expect-source`와 `--expect-target`을 제공한다.
빌드 기준은 `2c4fa62` 위의 미커밋 버전 변경이다. 게시용 최종 커밋 빌드는
태그 워크플로에서 다시 수행해야 한다.

원시 로그와 산출물은 제품 primary의
`tmp/release-0-9-2-preparation-20261014/`에 owner·기준 커밋·보존 목적·digest와
함께 보존한다. snapshot은 설치하지 않았다.

GitHub 저장소 secret 이름 조회는 현재 토큰 권한으로 HTTP 403이다.
이는 `HOMEBREW_TAP_TOKEN`의 존재 여부를 확인하지 못했다는 뜻이며, 워크플로
secret이 없다는 증거가 아니다. 태그 게시 전 원격 워크플로 권한 확인이 남는다.

TASK302는 다른 활성 실행이 소유한다. 이 준비 작업은 해당 실행의 코드,
worktree와 인수 기록을 변경하지 않는다.
