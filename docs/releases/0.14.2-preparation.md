# 0.14.2 릴리스 준비

호환되는 기능 추가이므로 patch를 올린다. `VERSION`과 개발 기본 버전은
0.14.2이며 공개 계약의 제거는 없다. 기존 `--execution-id`/`--generation`은
그대로 받는다. 릴리스 노트는 생성하므로 CHANGELOG를 수기로 수정하지 않는다.

## 포함 변경

- `77068e218b401231635637befcf757bd88501ba8`: `integrate cleanup`과
  `integrate receipt`가 `--record <id>@<generation>`을 받는다. `run`과 같은
  파서를 쓰며 두 형식을 섞거나 한쪽만 주면 receipt를 읽기 전에 종료 코드 2로
  거부한다. 레거시 플래그는 도움말에서만 deprecated로 표기한다(ADR-0161,
  TASK-113, ISSUE-098). 빈 `--generation=`은 이제 거부된다.
- `b1a5def3f32d5b3cdb0aca27e12fcfcff79792ba`,
  `82480dc23e6de0651409eb6094511507438d5189`: `internal/tasksync` 패키지
  추가. 아직 어떤 명령도 import하지 않으므로 배포 바이너리의 동작은 바뀌지
  않는다.

## 검증·게시 경로

0.14.1과 같다. 필수 `make verify-release`는 source master CI, 전체 gate,
GoReleaser 설정 검사, 비게시 snapshot packaging 순서다. snapshot은 공식 stable
설치 증거가 아니며 이전 후보의 full PASS를 재사용하지 않는다.

공식 `.github/workflows/release.yml`은 VERSION 변경이 통합된 master push의 CI가
성공한 뒤 그 SHA를 태그하고 같은 job에서 릴리스와 Homebrew cask를 게시한다.
게시 후 tag SHA·archive checksum·cask 버전과 digest를 확인하고, 로컬은 공식
cask 채널로 갱신해 두 version surface와 실제 실행 경로를 검증한다.

이 문서는 동결 후보의 검증 요구를 기록한다. 실제 결과는 해당 SHA의
[CI 실행](https://github.com/Gizzahub/gzh-cli-gitforge/actions/workflows/ci.yml),
[Release 실행](https://github.com/Gizzahub/gzh-cli-gitforge/actions/workflows/release.yml),
[공식 릴리스](https://github.com/Gizzahub/gzh-cli-gitforge/releases/tag/v0.14.2)를 따른다.
