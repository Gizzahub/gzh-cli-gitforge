# 0.15.0 릴리스 준비

공개 계약의 제거가 있으므로 patch가 아닌 minor를 올린다. `integrate check`,
`integrate reconcile`, `integrate legacy-cleanup` 하위명령과 pre-mutation 기계,
레거시 플래그(`--expect-source`, `--expect-target`, `--owner-actor`,
`--owner-host`, `--owner-kind`, `--execution-id`, `--generation`)가 CLI에서
사라진다(ADR-0161 최종 표면, ADR-0205 결정 5, TASK-114). 최종 표면은
`integrate run`(`--source`, `--target`, `--record`, `--owner`),
`integrate cleanup`·`receipt`(`--record`), `queue`, `provision`이다. 어떤
호스트든 업그레이드 순서는 gz-git 먼저, ce 나중이다. 릴리스 노트는
생성되므로 CHANGELOG을 수기로 수정하지 않는다.

  독립 리뷰로 확인되었다.

  `5756e6f7c` 릴리스, 2026-11-04 제로-니드 증명) 충족.
- `17403bb4`: gzh-cli-core 의존성 bump (#19).
- `52ef273d`: tasksync co-process 문서 정정.

  validate).

## 검증·게시 경로

`make verify-release`가 `944fea97` master에서 통과했다(master push CI, 전체
gate, GoReleaser 설정 검사, 비게시 snapshot packaging). 이 준비 커밋은
버전·문서만 바꾸므로 그 게이트 증거가 그대로 적용된다. 또한 이 준비 트리에서
커밋 게이트가 non-Go 입력(VERSION) 때문에 verify-full 프로파일로 확장되었고,
확장 프로파일이 이 트리에서 exit 0로 통과했다(2026-11-04). 커밋 통합 후 master
CI가 성공하면 `release.yml`이 VERSION 0.15.0 > 모든 기존 태그 조건을 보고
그 SHA에 `v0.15.0` 태그를 만들어 같은 job에서 릴리스와 Homebrew cask를
게시한다. snapshot은 공식 stable 설치 증거가 아니다.

게시 후 tag SHA·archive checksum·cask 버전과 digest를 확인한다. 호스트 cask
갱신은 이 릴리스와 별도의 devenv 작업으로 남긴다.

이 문서는 동결 후보의 검증 요구를 기록한다. 실제 결과는 해당 SHA의
[CI 실행](https://github.com/Gizzahub/gzh-cli-gitforge/actions/workflows/ci.yml),
[Release 실행](https://github.com/Gizzahub/gzh-cli-gitforge/actions/workflows/release.yml),
[공식 릴리스](https://github.com/Gizzahub/gzh-cli-gitforge/releases/tag/v0.15.0)를
따른다.
